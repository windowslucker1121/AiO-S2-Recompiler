# Platform 2 platform services: cross-check against Eglantine NX2_NOTES.md

Source: `NX2_NOTES.md` on branch `nx2` of github.com/Djihads80/Eglantine (an Eden fork that runs title C and title F; GPL-3.0, local clone in `refs/Eglantine`, commit 3060454). The file has 156 numbered rows of "where boot stopped, what the protocol needs, what Eden does" plus the sections Titles and Prioritized next steps. Rows 123-128 are numbered twice in the source; the second set is listed as `123b` ... `128b` here, and the table keeps the source order. `T1`, `T2`, `N3`, `N4` are the facts that sit outside the numbered table.

Compared against: `runtime/src/kernel` (SVCs), `runtime/src/core/switch2.cpp` (the `game::Platform::Switch2` HLE), `runtime/src/services` (IPC), `runtime/src/media/video_codec.cpp`, `runtime/src/gfx/nvn`, `tools/shaders/ampere`, and the SDK itself where a note and our code disagree (disassembly of the title A `sdk` module). Read-only: nothing was run.

## What kind of project this is, and why most rows are "n/a"

Eden has to be the console: it runs the real GPU driver stack (gsv, gpu, vi2, syncpt, NvRm) against an emulated GPU, so most of its notes are about the protocol of those services and the emulated GPU front end (pushbuffers, MME, QMD, puller). nxrt replaces that whole layer: `nv::InitializeGraphics`, the `nn::vi::*` layer/display calls and the `nn::codec` video decoders are host HLE (`core/switch2.cpp`, `media/video_codec.cpp`), and NVN itself is implemented on the host Vulkan device. Those IPC commands are never sent by the games we run (their logs show `aud:u`, `appletOE`, `hid`, `fsp-srv` ... and no gsv/gpu/vi2/syncpt service). Rows about that layer are marked `n/a` when the thing they describe does not exist here, and `differs (kept)` when something plays the same role differently.

Verdicts: `matches` (same behaviour, same fact), `differs (fixed)` (we differed on something a platform 2 title can hit; fixed in this branch), `differs (kept)` (we differ on purpose, reason in the row), `not implemented (done)` (missing, implemented now), `not implemented (documented)` (missing, what it would take is in the row), `n/a` (the note describes Eden internals or a layer nxrt does not have).

## Needs an in-game check

- svc 0x80 + QueryMemory: NVN2 may now see attribute 0x20 where it saw 0 before. If a platform 2 title's memory-pool init asserts on the attribute, it would show at boot as a pool creation failure; before it could only have been the other way round. Title A and title C boot is the check.
- Title C animated colliders (course objects; row 150): the claim that compute output reaches the CPU without a copy-back is by design, not observed.
- audren: any title whose log shows `library revision REV16`/`InvalidUpdateInfo` before; nothing known.

## Priorities from the census (work/audit/nvn_use_*_summary.md, census_*_summary.md)

Ordered by what the notes say breaks a game and how many call sites the census finds:

1. **Mesh/task shaders (rows 89, 97), title C**: `nvnCommandBufferDrawMeshTasks` is called at 9 sites and is a stub; the shader census finds 19 stage 6/7 blocks (ISBEWR is undecodable in our decoder). Eglantine saw high-detail LODs, foliage and cacti drawn this way (flicker and pop-in when skipped). Title I has 3 more sites (`DrawMeshTasks3D`, `...Indirect`), title B 1. What it takes is in row 89. This is the largest open gap that any note describes.
2. **DLSS (row 64), title I**: 28 DLSS functions are called, `EvaluateDlss` at 2 sites, all stubs. Eden's stand-in is a bilinear blit input to output. Needs the `NVNdlssParameters` layout first (row 64).
3. **Not in the notes, but the census flags them**: `nvnProgramInitializeFromBuilder` + `ProgramBuilderSetDefaults/SetDevice/SetShaders` (7 sites in title C and title B), `PushGraphicsConstants`/`PushComputeConstants` (title I 5/6 sites), `SetGeometryProcessingMode` (title C 18), `ShadingRateImagePalette` (title C 60, VRS), `SetComputeOverlapMode` (hint). Eglantine ran titles that use these through the real driver, so its notes say nothing about them; whether each is harmless as a stub is a separate review.
4. **GameChat/camera (rows 123-127)**: only for a title that runs `nn::chat::Initialize` (title C 1.8.0 per the notes; our dump is the base version). `chat:u` is there now, the gsv half is documented in row 124.

## Seen in Eglantine's code, not in the notes

- `auddmg:u` and `audsmx:u` are in the title C NPDM and Eden serves both (`nx2_audio_device_manager.h`); ours falls to the logging stub. Not requested in the title A run.
- `IApplicationProxy` getters 50/70/80/90 and `ICommonStateGetter` 2010 are answered by Eden with auto-stub objects / zeroed replies; ours has none of them. Nothing we run asks.
- `hid` 214 (Eden `SendNx2VibrationValues`, never fails) matches our 214 (`SendVibrationValues2`).
- Eden serves an empty system-data archive for platform 2 title ids; not checked in `fs.cpp`.
- Switchbrew lists more [S2] SVCs (0x81, 0x82, 0x84, 0x85, 0x87, 0x88); the title C SVC mask only has 0x80 of them, so only 0x80 matters for applications.
